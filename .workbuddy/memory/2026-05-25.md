## 留言板 Blob Key 重构（仅 key 设计，未拆 store）
- 背景：原方案所有 entry 都用 `msg:<reverseTs>:<id>` 前缀，list 主留言时会被回复拖累。
- 决策：保留单 store `guestbook`，仅改 key 前缀
  - 主留言：`msg:<reverseTs>:<id>` 不变
  - 回复：`re:<replyTo>:<reverseTs>:<id>` —— 前缀含父 messageId，便于按主留言精确拉回复
- 改动文件：
  - `netlify/functions/post-message.js`：写入时按 isReply 选择前缀；引入常量 `MSG_KEY_PREFIX` / `REPLY_KEY_PREFIX`
  - `netlify/functions/get-messages.js`：list 同时扫两个前缀（`Promise.all`），合并 blobs；分类仍以 `entry.replyTo` 字段为权威，兼容旧数据
- 兼容策略：旧回复仍在 `msg:` 下，靠 entry 字段分类，无需迁移
- 前端无需改动：`blobKey` 只在 DEBUG_MODE 下展示用，不解析；前端 → 后端协议 `messageId="re:xxx"` 与 blob key 是两个层面
