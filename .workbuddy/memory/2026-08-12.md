## CRT pow 查表优化

### 改动（js/crtEffect.js，纯计算优化，零视觉差异）
- 新增模块级 `barrelIntensityLUT` / `barrelBowLUT`（Float32Array，2049 项，覆盖 normalizedY ∈ [-1,1]），用查表替代每帧 ~570 次 `Math.pow(Math.abs(ny), 1.7)`
- 新增 `updateGeomCache(w,h)`：resizeCanvas 时预缓存 halfW/overscan/negOverscan/wPlusOverscan/edgeCompressW/curveStrengthH/invH，消除 drawScanLinesBatch 每帧每行 ~2000 次重复乘法
- drawScanLinesBatch：`if(!BARREL.ENABLED)` 提到循环外分两支；桶形畸变支用 LUT 查表 + 几何缓存
- LUT 精度 1/1024，最大误差 < 0.001px，对 alpha=0.08 扫描线无可感知差异

### 优化后测试（1280×800 / 5s，同基线配置）
- CRT 开启：54.3 FPS（[56,54,54,54,55,53]，5秒 326 帧）
- CRT 关闭：60.2 FPS（不变）
- 差值：-5.9 FPS（相对 -10.9%）

### 结论
- 软件渲染下 FPS 提升不显著（54.0→54.3，在采样噪声内）。根因：软件渲染瓶颈在 570 段 quadraticCurveTo 的 stroke 光栅化（CPU 像素填充），LUT 优化的是参数计算，被光栅化开销掩盖
- LUT 优化在真实硬件加速环境下收益更明显（光栅化交 GPU，CPU 侧 pow/乘法占比上升），且零风险，已保留
- 印证报告结论：Canvas 2D 路径在"不改画面表现"约束下已到极限，显著提升需 WebGL 着色器重写（P2 架构级）

## 硬件加速复测（去掉 --disable-gpu + --ignore-gpu-blocklist）

### 1280×800 / 5s
- CRT 开启：59.2 FPS（[59,58,61,59,59,59]，min 58，max 61，5秒 355 帧）
- CRT 关闭：60.2 FPS（[60,60,60,61,60]）
- 差值：-1.0 FPS（相对 -1.7%）

### 结论
- GPU 加速下光栅化交 GPU，CRT 仅损 1 FPS，接近 vsync 满帧，**真实用户无掉帧问题，无需 WebGL 重写**
- 软件渲染 54 FPS 是 --disable-gpu 放大代价，不代表真实体验
- LUT + 几何缓存优化保留：零风险，硬件加速下 CPU 侧计算减少，对高 DPI/多标签场景有益
- 基准脚本当前配置：1280×800/5s/硬件加速（已从 4K/15s/软件渲染改回）

## 高分辨率掉帧诊断（用户反馈：视窗铺满屏幕+滚动掉帧）

### 1920×1080 硬件加速静态测试
- CRT 开启：**29.8 FPS**（[30,29,30,30,30]，稳定 30，每帧~33ms）
- CRT 关闭：60 FPS
- 对比 1280×800 的 59.2 FPS：像素数 1.02M→2.07M 翻倍，FPS 腰斩，开销随面积线性

### will-change 合成层实验（已回退）
- `.crt-effect` 加 `will-change: transform; transform: translateZ(0);` 后重测：仍 29.8 FPS，无改善
- 结论：瓶颈在 Canvas 2D 每帧光栅化 2M 像素本身，合成层无法减少这部分
- 改动已回退（无效且占 GPU 内存）

### 根因
- Canvas 2D 路径：每帧 570+ 段 quadraticCurveTo + 3 次 stroke，光栅化像素数随 canvas 面积线性增长
- 1080p 突破 16.6ms 帧预算（~33ms/帧），掉到 30 FPS；滚动叠加合成压力更卡
- LUT 优化（已做）救不了：光栅化是大头，参数计算占比小
- 结论：Canvas 2D 在高分辨率下无法满帧，需 WebGL（GPU 并行）或降分辨率（减像素）

## WebGL CRT 重写（解决 1080p/4K 掉帧）

### 决定
- 完全重写为 WebGL 片元着色器，不保留 Canvas 2D fallback（代码聚焦；不支持时 warn + 静默）
- 保留原 API（initCRT/enable/disable/destroy）+ 事件管理 + CONFIG

### 改动（js/crtEffect.js，~410 行）
- 移除：Canvas 2D 路径、LUT/几何缓存、OffscreenCanvas 静态缓存
- 新增：WebGL context（premultipliedAlpha:false）、顶点+片元着色器（#define 从 CONFIG 注入）、单次 drawArrays 全屏四边形
- 片元着色器逻辑：
  - 桶形畸变 Y 补偿：bowY = 4t(1-t)*bowOffset，把弯曲扫描线拉直
  - 扫描线：bg→R→G→B source-over 非 premultiplied 模拟，3 通道独立 + waveOffset 振荡
  - 暗角：分段 vigCurve 复刻 Canvas gradient stops (0→1, 0.24→0.62, 0.58→0.21, 1→0)
  - 四角：4 角循环 + cornerShadowCurve/cornerHlCurve 复刻 radial gradient stops，shadow multiply + hl source-over 蓝光
- `glslF(n)` helper 确保 #define 整数加 .0（FREQ=50 是 int，`y/FREQ` 报 float/int 类型错误）

### 验证
- 1080p 硬件加速：CRT 开启 60 FPS（[61,60,59,61,59,60]），关闭 60.2 FPS，差值 -0.2 FPS
- vs Canvas 2D 1080p 29.8 FPS：从 30 翻倍到 60，根本解决
- 截图 `crt-webgl-preview.png`（1280×800）已 present；dev server 8088 可浏览器看动态效果
