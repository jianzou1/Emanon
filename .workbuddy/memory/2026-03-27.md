## SPA 化可行性调研

- 调研结论：**完全可行且值得做**
- 推荐方案：**Phase 1 — 内存缓存 + innerHTML 替换**（渐进式，最小改动）
  - 改造 `tabHandler.js`：`preloadTabs()` 将 fetch 结果存入 JS 内存 Map
  - 页签切换时从内存取 HTML 注入 `#main`，跳过网络请求
  - `handlePageLoad()` / cleanup 逻辑完全复用，无需修改各模块
  - 保留 PJAX 作为 fallback（缓存 miss）和文章详情页/密码页导航
- 主要风险点：ID 冲突（若用 CSS display 方案）→ Phase 1 用 innerHTML 替换避免此问题
- 预计工作量：~2 小时（仅改 tabHandler.js + 测试）
- 对 post 页面、CRT、多语言系统无影响

## SPA 化 Phase 1 实施完成

### tabHandler.js 改动
- 新增 `static htmlCache = new Map()` 内存缓存（URL → #main innerHTML）
- `cacheCurrentPage()` — 首次加载时缓存当前页签的 #main 内容
- `preloadTabs()` — fetch 其他页签 HTML，用 DOMParser 提取 #main innerHTML 存入缓存
- `handleTabClick()` — 缓存命中时直接 innerHTML 注入 + `history.pushState()` + 调用 `onPageLoad()`；缓存 miss 时 fallback 到 PJAX
- 构造函数新增第 4 参数 `onPageLoad`（回调），由 main.js 传入 `handlePageLoad`
- `isTabUrl()` — 判断 URL 是否属于页签（供 popstate 使用）

### main.js 改动
- `handlePageLoad` 声明提前到 `refreshTabHandler` 之前（因为要作为参数传递）
- `refreshTabHandler()` 调用 `new TabHandler(selector, data, pjax, handlePageLoad)`
- `langManager.applyTranslations()` 移入 `handlePageLoad()` 内部（统一处理）
- 新增 `skipNextPjaxComplete` 标志位：防止 popstate 内存缓存处理后 PJAX 重复触发
- 新增 `popstate` 监听器（捕获阶段）：页签 URL 缓存命中时直接注入 + 标记跳过 pjax:complete
- `pjax:complete` handler 加入 `skipNextPjaxComplete` 检查
